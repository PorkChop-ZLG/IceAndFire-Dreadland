## 1. 目标、范围与保留行为

目标是修复 DP-001 至 DP-009，并保留已有存档和传送门形态。完成条件是行为测试、存档兼容和光影画面验证均有证据；仅编译成功不能关闭这些问题。

必须保留：

- Minecraft 1.21.1、NeoForge 21.1.233、Java 21；不为修复擅自升级平台或前置依赖。
- 模组 ID、传送门方块/方块实体/钥匙注册 ID；已有资源路径尽量保留。
- 固定外框 5×7、内部 3×5；X/Z 两种朝向、可省略四角、混合框架标签方块。
- 悚域之钥激活；成功激活时生存消耗一把、创造不消耗。
- `frame_bound=true` 的框架依赖和拆框清理；旧出口及直接放置的 `frame_bound=false` 门块继续可用。
- 非悚域维度进入悚域；悚域返回主世界。不要自行改成“返回原维度”。

- 无光影时的自定义门面效果、现有粒子和冷却/离门后再次进入的基本体验。

范围之外：修改悚域噪声、教堂、龙试炼、画像、钥匙配方，增加双向门配对数据库、强制 Iris 前置、发布版本、推送或合并。

## 3. 统一行为约定

### 3.1 接触与计时

- 接触状态只在服务端创建，普通未接触生物不分配附件。
- 可从门块 `entityInside` 记录接触，但一次 tick 内跨多个门块的回调必须去重。
- 服务端最终更新必须再次确认实际接触，不能只依赖上一 tick 的标记。采用与门块实际几何一致的包围盒检查；不把仅站在附近当作接触。
- 同一实体每个服务端 tick 最多推进一次，包括克隆换维度后的实体。
- 计满 N 个合格接触 tick 后触发，N 来自配置；N=0 在首次确认合格接触的更新中触发。
- 最后一次更新时已离门则取消，不能根据旧零值先传送。
- 仅处理现有范围内的 `LivingEntity`。检查存活、`canUsePortal(false)`、跨维度资格及目标维度启用状态。
- 本计划默认拒绝乘客以及载有乘客的实体；拒绝时不拆乘。载具整体传送不在本轮范围。
- 成功后在目标实体上抑制再次触发，直到其离开门。失败清除“已成功”状态；同次接触可进入失败等待离门状态，向玩家提示离门重试，避免每 tick 重试。

建议状态只有空闲、计时、迁移中、成功等待离门、失败等待离门。空闲状态不需要保留附件；迁移中标记必须与“已成功”区分。

### 3.2 目标搜索与安全判断

两个方向都执行相同的安全规则，不能只修进入悚域的分支。

建议默认搜索预算如下。这些是待实现的内部常量，不新增面向玩家的配置项：

| 项目 | 建议值/规则 |
| --- | --- |
| 水平搜索半径 | 投影 X/Z 周围 32 格 |
| 新出口候选点上限 | 64 个，按距离稳定排序并去重 |
| 单次额外同步加载区块上限 | 25 个，包含模板占地区块；已加载区块优先 |
| 超出预算或无安全点 | 明确失败，不扩大为无界搜索，不强行覆盖 |
| 高度 | 从目标维度地表候选得到，再核查真实空间；不写死 64、100 等 Y |

优先定位附近已存在的门。旧门均有方块实体，可利用有限区块中的门方块实体收集候选，避免扫描整个半径内每一列的全部高度。对同一门的多个方块候选去重；保留旧无框出口的识别，不强制要求其具有新框架。

每个候选必须检查：

- 世界边界与完整建筑高度范围；实体自身高度/宽度，而非固定两格空气。
- 实际碰撞、脚下支撑、液体、火、岩浆及其他已识别危险地面。
- 可复用门的实际可站立空间；不能仅凭一个门方块存在就认定可用。
- 新结构完整写入范围及相邻安全等待位置，均处于预算内。

无现有门时，悚域可生成受保护的新出口；主世界只寻找安全落地位置，不新增原先不存在的自动主世界出口结构。宽大生物找不到足够空间时安全失败，不缩小实体或强行塞入门。

### 3.3 出口写入保护

保持当前 `dread_exit_portal.nbt` 的外观与旧注册 ID。运行时从模板取得大小和写入内容，不把 252 个方块等数据硬编码为永远不变的假设。

- 对模板中的空气与实体方块统一预检，不能只检查中心或仅忽略模板空气。
- 优先把结构放在自然地表上方的空旷空间。允许替换的已有内容限于空气和经过明确筛选的轻量植被/积雪；带流体、带方块实体、受保护或不可破坏的方块一律拒绝。
- `canBeReplaced()` 不能直接作为唯一白名单。可替换方块中也可能有不应清理的内容。
- 本轮不挖山、不替换实心地表来凑出空地，不清除建筑；不合格就换候选或失败。
- 检查底部支撑和邻接可通行空间，不能得到悬浮且无法走出的出口。
- “非空气但恰好等于模板方块”也不自动视为可覆写，否则可能误改玩家建筑。
- 允许清除的轻量植被须记录原状态；回滚按本次写集恢复，不掉落或复制原物品。

方块来源无法从普通 BlockState 判断。因此不承诺识别所有玩家放置的植物；承诺的是保守写入白名单、保护容器和实心建筑，不虚构通用领地保护能力。

### 3.4 旅行、取消与出口放置的顺序

**不能简单把 `placeInWorld()` 移到 `changeDimension()` 前面。** 那样旅行被取消时仍可能生成出口；也不能先把实体移到需要清障才能站立的位置。

对于已有安全门或主世界安全落点，直接迁移到已验证位置；不做任何结构写入。

对于需要新建悚域出口，采用以下顺序：

1. 只读生成放置计划，包含模板写集、原状态、安全等待点和最终门内位置。安全等待点必须在写集和模板最终碰撞范围之外，已有支撑并足够容纳该实体。
2. 保存源维度与源安全位置，设置临时“迁移中”防重入状态；目标为空、资格不符、预算不足等在此之前失败。
3. 调用正常的 `changeDimension()`，目标位置设为安全等待点，保留 NeoForge 的旅行取消事件。不得手动重复触发事件，也不得强制绕过事件。
4. 仅在正常成功回调中操作返回/回调收到的目标实体。失败返回 `null` 时，不生成出口，清理源实体的临时状态。
5. 成功回调中重新核验计划涉及的世界状态；一致才应用受保护写集。使用同一受检计划的数据，避免预检一套而 `placeInWorld()` 无约束写另一套。
6. 确认结构完整、门块存在、最终空间安全后，在同一次服务端调用内把实体移到最终位置，再提交成功等待离门状态。不要把尚未完成的出口留到下一 tick 才准备。
7. 接入成功后的声音、必要的原版传送区块票据和运动/坠落状态处理；不要添加永久强加载。只在完成时播放成功效果。

不预设 `placeInWorld()` 返回 true 就代表所有方块完整写入。需核对实际放置结果及安全空间；若当前版本不能方便地使用同一受检模板写集，可实现有限的专用放置器，但不得复制整套世界结构系统。

| 失败位置 | 必须采取的行为 |
| --- | --- |
| 预检、搜索、目标缺失、模板缺失 | 实体留在源世界；目标零写入；清理临时状态并反馈 |
| 正常旅行事件取消 | 源实体保留；目标零结构写入；不标记成功 |
| 成功迁移后计划失效/结构部分失败 | 停止后续放置，回滚本次已写位置；不得把实体移到未完成的门里 |
| 迁移后放置失败的实体安置 | 优先通过正常 API 尝试返回重新验证过的源安全位置；如返程也被事件取消，保留在写集外的安全等待点并反馈，记录这次未完成 |

回滚仅覆盖本次写集，不保证撤销其他模组事件的任意外部副作用。若写后状态已被外部逻辑另行修改，不得盲目覆盖他人新状态；记录位置并作为失败处理。安全等待点必须不受放置与回滚影响，这是失败兜底的基础。

- 不增加 Iris 必选依赖，不要求用户更改 Iris 配置；不要因为安装 Iris 但未启用光影而禁用原有效果。
